# VeilGuard AI: Privacy Dashboard

This document describes every panel in the Phase 3c privacy dashboard, its data source, the exact formulas used, retention policy, the pause switch, export formats, and the metadata-only guarantee.

---

## Metadata-Only Guarantee

The dashboard never displays, exports, or logs:
- Raw prompt text or any substring thereof
- Matched entity values (e.g. real names, phone numbers)
- Placeholder-to-original mappings (e.g. `[PERSON_1] → Rahul Sharma`)
- Bearer token or any credential

Every number on screen comes from **`StoredEvent` metadata fields only**, as validated by `sanitizeEvent()` at both write-time (in `events-store.ts`) and read-time (in `summarize()`).

## Dashboard Panels

### 1. Summary Cards

| Card | Field | Source |
|------|-------|--------|
| Messages checked | `totals.checked` | Count of valid `StoredEvent` records after filter |
| Sent unchanged | `totals.by_user_choice.auto_allowed` | Events where `user_choice === "auto_allowed"` |
| Sent sanitized | `totals.by_user_choice.sent_sanitized` | Events where `user_choice === "sent_sanitized"` |
| Blocked or cancelled | `by_user_choice.blocked + by_user_choice.cancelled` | Sum of blocked and cancelled events |
| Engine blocked | `totals.by_user_choice.failed_closed` | Fail-closed events (engine unreachable) |
| Documents scanned | Always 0 | Document scanning not available until Phase 7 |

### 2. Decision Tiers

Bar chart of `by_decision` counts. Labels are plain-language descriptions — **not risk scores**:

| Decision value | Dashboard label |
|---------------|----------------|
| `allow` | No sensitive content found |
| `redact` | Sensitive details found (redaction recommended) |
| `require_approval` | Needs your decision |
| `block` | Blocked |

The engine does not produce a numeric risk score. This dashboard does not invent one.

### 3. User Actions

Bar chart of `by_user_choice` counts:

| Choice | Meaning |
|--------|---------|
| `sent_sanitized` | Sent with sensitive content replaced |
| `sent_original` | Sent original after explicit second confirmation |
| `edited` | User chose to edit before sending |
| `cancelled` | User dismissed the overlay without sending |
| `failed_closed` | Blocked because engine was unreachable |
| `auto_allowed` | Sent unchanged (engine found no sensitive content) |
| `blocked` | Blocked by policy without user action |

### 4. Sensitive Information by Category

Sum of `category_counts` values across filtered events. For example, if an event has `{ PII: 2, GOVERNMENT_ID: 1 }`, the dashboard adds 2 to PII and 1 to GOVERNMENT_ID.

### 5. Rules That Fired

Counts of `rule_ids` entries across filtered events. If the engine is reachable, the plain-language reason is fetched from `GET /policy/profiles` via background `FETCH_PROFILES`. If the engine is not reachable, "reason unavailable (engine not reachable)" is shown.

### 6. Activity — Last 14 Days

Daily bucket counts for the last 14 local days, with zero-filled gaps. The bucket date is the **local calendar date** of `event.timestamp` (not UTC).

**Formula:**
```
date = formatLocalDate(new Date(event.timestamp))
// formatLocalDate uses d.getFullYear(), d.getMonth()+1, d.getDate()
// — all in local time, not UTC
```

A 14-day skeleton is built from `refDate` (today) backward 13 days. Events outside the 14-day window are not counted in this bar but are included in other panels if they pass the time range filter.

### 7. Observed Engine Latency

Percentiles of `latency_ms` values across filtered events.

**Method:** Nearest-rank percentile (NIST / Wikipedia standard).

```
rank(P, N) = ceil((P / 100) * N)
index = max(0, min(N - 1, rank - 1))
value = sortedValues[index]
```

Edge cases:
- `N = 0` → returns 0
- `N = 1` → returns `values[0]`

Labeled **"observed on this device, not a benchmark."** These numbers describe engine latency as seen from the extension on this specific device and network. They are not detection accuracy figures.

### 8. Benchmark Panel

Placeholder: _"No benchmark results are bundled yet."_

The benchmark display (Phase 6) will read a bundled summary file generated by the Phase 6 benchmark run.

### 9. Recent Events Table

Paginated table of 25 events per page, newest first. Columns:

| Column | Source field | Note |
|--------|-------------|------|
| Time | `timestamp` | Formatted as local HH:MM:SS |
| Destination | `destination` | Hostname only, validated |
| Profile | `profile` | Policy profile name |
| Decision | `decision` | Color-coded tier badge |
| User action | `user_choice` | Plain-language label |
| Categories | `category_counts` keys | Comma-joined category names |
| Rule IDs | `rule_ids` | Comma-joined rule identifiers |
| Latency | `latency_ms` | Rounded to nearest ms |

**Zero text columns.** No column shows prompt text, entity values, or sanitized text.

> Counts describe activity on this device. They are not a measure of detection accuracy.

## Controls

### Time Range
- **Last 24h** — events from the last 24 hours
- **Last 7d** — events from the last 7 days
- **All time** — all stored events (default)

### Filters
- **Destination** — filter by `event.destination` hostname
- **Profile** — filter by `event.profile`
- **Decision tier** — filter by `event.decision`

All filters combine with AND semantics.

### Export

Downloads a file containing only whitelisted fields. The exact field set is:
```
timestamp, destination, profile, decision, user_choice,
rule_ids, category_counts, entity_count, latency_ms, source, outcome
```

- **JSON** — pretty-printed JSON array
- **CSV** — comma-separated, values quoted

No text fields, no entity values, no token, no raw prompt content are ever included in exports.

### Clear History

Two-step confirmation: click "Clear history", then "Confirm clear". Clicking "Cancel" leaves events intact. On confirm, `chrome.storage.local` keys `vg_events` and `vg_audit_log` are removed and the page reloads.

### Pause Recording Switch

Toggles `chrome.storage.local.vgRecordHistory` between `true` (recording) and `false` (paused).

> **Important:** Pausing history **never pauses protection**. All interception, engine analysis, and review overlays continue to operate normally. Only the metadata recording step is skipped.

---

## Retention

- Events are stored in `chrome.storage.local` under key `vg_events`.
- The ring buffer cap is **1,000 events**. When a new event would exceed 1,000 total, the oldest event is evicted.
- Events are lost if:
  - The extension is removed from Chrome (storage is cleared on uninstall).
  - The user clears history via the dashboard.
  - Chrome's local storage is cleared externally.
- There is no cloud backup, sync, or remote transmission of events.

## Event Schema

Each stored event has exactly these fields (others are discarded by `sanitizeEvent()`):

```ts
interface StoredEvent {
  timestamp: string;       // ISO 8601
  destination: string;     // hostname only, validated
  profile: string;         // policy profile name
  decision: EventDecision; // "allow"|"redact"|"require_approval"|"block"
  user_choice: EventUserChoice;
  rule_ids: string[];      // max 20 entries, /^[A-Z0-9_.]{1,64}$/
  category_counts: Record<string, number>; // known categories only
  entity_count: number;    // non-negative, finite
  latency_ms: number;      // non-negative, finite
  source: EventSource;     // "prompt"|"document"
  outcome: string;         // legacy field, used for user_choice normalization
}
```

All free-text fields are forbidden. `rule_ids` entries containing spaces or prose fail the `/^[A-Z0-9_.]{1,64}$/` regex and are silently dropped.
